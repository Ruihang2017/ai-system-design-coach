# Handover: Fix /query 500 misreported as CORS error

**Date:** 2026-05-26 11:13

## What Was Done
While testing with a real OpenAI key, `POST /query` returned a 500 that the browser
reported as a CORS error ("No 'Access-Control-Allow-Origin' header"). Systematic
debugging (reproducing the call directly with the configured key + running Qdrant)
showed the **real cause is external**: OpenAI returns **HTTP 429 `insufficient_quota`**
— the account/project tied to the key has no available credit. That is a billing
setting at OpenAI, not a code issue.

The investigation also exposed a real API defect: unhandled pipeline exceptions
propagated past the CORS middleware to Starlette's outermost error handler, so the
resulting 500 carried no CORS headers and the browser masked the true error. Fixed
so any upstream failure now returns a clean, CORS-headed **502** with the real reason
in `detail`, and the UI shows that reason instead of a bare status code.

## Files Changed
- `backend/app/main.py` — `/query` wraps `orchestrator.answer` in try/except and raises `HTTPException(502, detail=...)` (routed back through CORS); logs the full traceback.
